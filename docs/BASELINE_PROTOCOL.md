# Baseline 复现与后续优化边界

研究目标：在已有 KV 选择性重算方法上提高任务质量，同时使端到端 TTFT 基本不增加。首轮建议把均值 +5% 作为待采用的延迟约束，并同时比较 P95；这是实验目标，不是已有结果。

## 固定的第一项 baseline

采用 LMCache v0.3.13 官方发布的 CacheBlend 实现，commit 与文件哈希见 `sources.lock.json`，搭配 vLLM v0.11.0、PyTorch 2.8.0。
选择这个版本是因为其官方模型适配器明确支持 Qwen3；此前检查的 v0.3.7 blending 适配器只支持 Llama。
现有 Qwen3-8B 是发布实现所支持模型上的运行复现，并非原论文全部配置的逐图复现。

该版本默认示例在检查层 1 根据旋转后 K 的平方差做 top-k 选择，比例为 0.15，随后复用该选择。具体以锁定的 `lmcache/v1/compute/blend/blender.py` 为准。
论文描述、不同发布版本与默认示例可能存在差别，因此报告必须写明 commit、检查层、比例、注意力后端和缓存来源。
当前已有 tail5 / hybrid10 仅是位置启发式诊断，不作为 CacheBlend、PatchKV 或 A³ 的实现。

## 阶段验收

1. 环境：原工程状态校验通过；专用 venv 导入路径正确；依赖具有完整锁文件；上游源码保持干净。
2. 执行：官方重排文本块示例完成；不仅有文本输出，还必须在日志中看到官方 top-k 选点发生。
3. 正确性：先验证完整重算、精确前缀在新框架下的控制结果，再测 CacheBlend；原始标准任务与中间编辑衍生任务分开记录。
4. 质量—延迟曲线：同一模型、任务、缓存来源、批量与计时边界，扫描固定的重算比例。DEBUG smoke 时间不进入性能结论。
5. 优化：从已验证的 baseline checkpoint 创建研究分支，只改一个机制；参数在开发集确定，最终测试使用独立样本。

CacheBlend 的官方 FlashInfer sparse 选项也需要验证，不能把默认后端的已知限制当作自己的新机制；正式对比应包含可用且较强的官方配置。
对相同重算比例的比较仅用于解释机制；主要结论必须比较相近实测 TTFT 的工作点，并计入选择、检索、搬运、调度和修复成本。
PatchKV 面向中间编辑，A³ 已研究问题相关性，它们都是设计新机制前必须核对的强相关工作。

## 时间与质量口径

- 官方 smoke 的 `one_token_generate_wall_ms` 是离线 API 一 token 的调用耗时，含框架处理；`engine_ttft_ms` 是引擎内部首 token 时间。二者均不等同于客户端 HTTP TTFT。
- 正式在线比较从客户端发送请求到收到第一个生成 token；已有缓存的初次构建和初始化开销另报。若某方法为了处理本次新编辑而临时准备缓存，这项工作计入本次端到端 TTFT。
- 输出不同不等于答错。使用 EM/F1/可执行任务测试评分，并单列完整重算答对、近似方法答错的事件。
- 完整重算质量过低的任务不能用于证明“精度保持”；仍保留全部结果，不能按测试集正确率挑题。
- 连续编辑使用各方法自己的缓存链，同时增加精确缓存重新开始的对照，以区分题目难度变化和误差积累。

## 中间编辑适配限制

固定版本 `LMCacheEngine.lookup` 遇到第一个缺失块即停止；直接将从未缓存的 B′ 插入旧上下文，只会命中 A，不能据此评价 C 的融合。
当前 HTTP pilot 为 CacheBlend 先发送独立 B′ 请求建立块缓存，然后发送最终 A+B′+C；其准备时间计入客户端 TTFT，并单独保留主请求 TTFT。启用官方 `save_unfull_chunk`，使末尾 C 不因截断产生不同哈希。
这是针对编辑场景的显式输入适配，并未修改官方 lookup 或 selector。正式研究应区分“新块已经离线准备好”的原始融合场景与“编辑到达后在线准备新块”的场景。
运行日志必须证明命中越过编辑区域并进入 C；不能只凭生成成功或命中数大于零认定后缀复用已经发生。

## 修改与回退

上游 Git checkout 保持在锁定 commit。官方初始化兼容修改保存为项目内 patch，脚本对原文件哈希和目标目录进行检查后，才应用到专用 venv。
实际联调还需要在 LMCache 请求适配器中将 vLLM 0.11 的 `ConstantList` 转为普通 `list` 后送往序列化接口。此修改独立保存，不改变 token 值或重算算法。
另两个 buffer connector 调用省略了 C++ 声明默认值为 `False` 的 `use_mla` 参数，但 pybind 接口没有暴露默认值；兼容补丁在全注意力路径显式补齐 `False`。CUDA 内核和选择器均保持上游原样。
后续算法补丁和运行配置进入研究分支；不要只修改 `.venv/site-packages` 而不保存补丁。
基线回退使用已验证 tag 的新 worktree 与独立环境，避免覆盖仍在工作的优化分支；本项目所有提交先留在本地，不自动推送。
