固定严格 token 因果 mask、检查层前 KV 写回修正、K 差异打分、检查层 1 和总重算 10%。
原策略为全局 top-k；query 策略从同一预算预留最后 64 token，剩余按原分数选取。
所有 480 个开发/验证初始及编辑输入均通过问题文本和 assistant 模板的末段覆盖检查。

开发使用固定 12 来源、两种布局、每链三次编辑；验证为原 96 来源 early8k，每来源三次编辑。
两组各两次新服务重启重复，顺序交换；288 个独立编辑事件、96 个来源，重复不增加独立来源数。
配置预先冻结，没有依据模型答案调整。验证来源此前已测过，不称为全新测试集。

## 解释边界

末段位置由固定 64-token 规则确定，不使用标准答案或支持事实位置；运行日志逐调用核对总选点数、强制数量和覆盖。两组都包含相同日志同步开销。
末段重算也有可能改变 full 本身错误时的偶然答对；因此全体正确率与 full 正确而缓存方案错误分开保存，不能仅看输出一致性。
该诊断仍复用 C 内的问题 KV，并在计算时修复；不等于完全切断 query 缓存。它只能检验当前预算分配的效果，不能代表所有问题感知选择方法。
同一问题被重算时仍可能读取其他位置的旧 KV；末段覆盖并不保证上下文更新已完整传播。
输入是事实前移加重复背景的 BABILong 编辑衍生压力测试，不是官方分数。单客户端串行，不涵盖吞吐、多模型、自然长文或近似 KV 每次回写后的误差累积。
系统资源未完全隔离；两轮运行与来源 bootstrap 不等于长期线上稳定性保证。
