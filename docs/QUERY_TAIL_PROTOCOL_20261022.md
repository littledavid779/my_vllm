# 固定预算的问题末段修复

在严格 token 因果 mask 和相同检查层前 KV 写回修正下，比较原 K 差异 top-k 与预留末段的策略。固定检查层 1、总重算 10%，预留最后 64 token，剩余名额按 K 差异选取。仅长度至少 1024 的 blending 请求启用预留，短 B′ 准备请求沿用原选择。强制部分从同一总预算中扣除，位置不重复，不增加总选点数。

运行前逐输入检查最后 64 token 包含完整 Question 文本和 assistant 模板。配置不读取标准答案，不依据本轮质量调节长度或比例。两组使用相同 C/问题缓存来源；这是当前上下文编辑适配的诊断，不能把问题重算直接当成新贡献。

开发为固定 12 来源、24 条链、每链三次编辑；保留 natural4k 与 early8k，主要看 early8k。验证为先前 96 来源 early8k 对照，每来源三次编辑，两次新服务重启重复，交换运行顺序。这些来源此前已评估过，不能称为全新未见数据；本轮不根据其答案调参。

两组新测 HTTP TTFT，包含新 B′ 的完整准备时间。原 native full/prefix 质量参考在输入、配置、事件完整性校验后复用，不当成新测延迟或重复观测。以全体任务准确率为主，另列 full 正确而缓存方案错误、否定条件分项与三次编辑。重复测量按来源聚类，不能增加独立样本数。两组增加完全相同的选点覆盖日志，开销计入 TTFT。

先做预算、唯一性、覆盖、原分数保护的 CPU 测试，再做开发小对照。执行失败、问题未覆盖、强制预算未生效或任一组不完整时先修复执行，不跳过异常事件。执行成功后冻结配置进入验证；即使开发无质量改善也保留负结果，不启动参数搜索。

继续投入的参考门槛：正确率增加至少 5 个百分点，平均 TTFT 和 P95 均不超过新测原策略的 1.05 倍；同时报告按来源聚类的 95% 区间。区间跨零时不宣称稳定增益。开发收益与验证分开汇报。

输入锁、补丁哈希、服务日志、逐请求输出存入数据盘独立工程；仅使用空闲 GPU 1。运行结束恢复算法补丁，并验证原工程保护记录。未测试并发吞吐、自然长文或逐次将近似缓存写回后的误差累积。
