# 第二轮结果：有条件的延迟空间，尚无稳健的精度优化

主实验完成了 108 个不同公开来源样本、两个布局、各三次编辑，共 3240 次测量。官方默认发布配置在原始布局上没有胜过精确前缀的平均 TTFT 和准确率；长后缀布局出现明显的延迟差距，但精度下降较大。
进一步核验发现，所锁定发布版本的执行后端存在因果位置和索引处理问题。因此这些精度差距不能直接当成论文选择策略的失败，更不能当成我们的新算法可改进幅度。本轮没有实现“总体精度提高、TTFT 基本不变”。

## 输入与执行

QA9 / QA2 / QA3 各 36 个源样本，排除上一轮索引 0、1；三类各 36 条不同事实序列。所有 300 个原始官方标签均通过解释器重放。样本选择与模型输出无关，全部错误与正确事件保留。

- `natural4k`：平均 3828 token，编辑点平均在 68.4%，后缀约 1153 token；保留源背景与事实位置。
- `early8k`：平均 8044 token，编辑点平均在 4.1%，后缀约 7666 token；事实前移，后接重复的去事实背景。它同时改变布局、长度和背景分布，只是受控衍生压力测试。
- 每种方法 648 个编辑事件；同一来源的两布局、三编辑相互依赖，不能当成六个独立样本。
- 独立 GPU 1、Qwen3-8B、LMCache 0.3.13 / vLLM 0.11.0。GPU 0 有其他任务，未隔离整机 CPU/内存；每个请求只测一次，因此延迟为筛查值。
- 客户端 SSE 首个生成 token 计时；新 B′ 准备请求全耗时计入 CacheBlend TTFT。初始化、首次播种和分词不在热请求 TTFT 中。
- 1944/1944 个 CacheBlend 编辑事件均验证命中至 C。三次编辑遵循上游实际缓存保存策略，没有将其误称为近似 C 每轮写回的误差传播实验。

## 后端核验与局部修正

代码/CPU 调用证据确认了以下发布实现行为：

1. 默认 FlashAttention 压缩离散 Q 后仅更新 Q 长度，仍以右下对齐的普通 causal mask 调用，未显式表达每个 Q 的原位置。
2. FlashInfer sparse 选项构建了 block mask，但切换 `is_causal=False` 的语句被注释，实际继续使用普通 causal 分支。
3. sparse mask 切片的原地整除会通过视图改写传入 token 索引；`arange(64)` 的第 31、63 项变成 0、1。该索引随后还用于 KV 写入。
4. 实际启用 sparse 分支后，定制 wrapper 与 FlashInfer 0.3.1 的 workspace/GQA 布局不兼容。先补 workspace 仍触发非法显存访问；最终改用 FlashInfer 自带公共 wrapper 并转换 NHD/HND 布局后运行成功。

固定每类排序前四个来源，共 12 来源；每布局 36 个编辑事件，独立于模型失败与否选取。此表均使用 FlashInfer、容量 16、单请求串行；修正版仅进行上述局部修正，没有修改 K 偏差打分、检查层、15% 预算或 block mask 的数值计划。

| 布局 | 配置 | 正确数 | 缓存新增错误 | TTFT均值 ms | P95 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| natural4k | 完整重算 | 20/36 | 0 | 322.47 | 336.95 |
| natural4k | 精确前缀 | 19/36 | 1 | 109.75 | 237.92 |
| natural4k | 发布版 sparse 开关 | 19/36 | 3 | 163.79 | 189.63 |
| natural4k | 激活 block-mask 的局部修正 | 12/36 | 11 | 170.09 | 204.57 |
| early8k | 完整重算 | 17/36 | 0 | 708.49 | 754.48 |
| early8k | 精确前缀 | 17/36 | 0 | 694.07 | 713.28 |
| early8k | 发布版 sparse 开关 | 10/36 | 8 | 244.42 | 272.47 |
| early8k | 激活 block-mask 的局部修正 | 14/36 | 5 | 253.31 | 281.54 |

长后缀正确率从 27.8% 到 38.9%，均值 TTFT 增加约 3.6%；原始布局却从 52.8% 降到 33.3%。两个布局合计正确数从 29/72 降到 26/72，没有总体改善。计时未重复，不能据此宣称延迟约束已满足。
FI 原始/诊断的 full/prefix 控制结果质量差异均为 0。FI 自身有一个 full/prefix 答案差异，FA 主实验没有；因此精确前缀与完整重算的输出也不能假定逐 token 位级一致。
诊断采用的 block mask 仍按 32 个离散查询分组近似，不代表逐 token 的严格因果已经验证；该修正不能被包装成新的准确率算法。

## 对研究空间的判断

- 本轮原始布局下，精确前缀的平均 TTFT 与准确率更好，继续围绕这个分布优化后缀复用的优先级低。其 P95 与近似方法存在不同权衡，不声称逐请求或所有延迟指标都占优。
- 早编辑、长后缀仍有值得检验的成本空间，也出现了跨来源的质量问题；但执行后端因素尚未排除，不能直接宣称论文方法有很大的精度提升余地。
- 下一项必要验证应固定同一打分与预算，以逐 token 严格因果执行作为参考，再区分 block mask、选择位置与缓存来源造成的误差。只有在可靠 baseline 上仍存在多来源、可低成本修复的错误，才进入新机制设计。
- 不把本轮用于构思的 12 来源作为最终测试集，不按这些失败例子定制新规则后再汇报其提升。
