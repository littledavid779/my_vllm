# 共同问题刷新后的新来源筛查

本轮检验：消除问题漏算后，固定尾部 64 是否还有增益；静态块首选择能否达到相同质量。
不预设新方法有效，不把适配规则称作原论文系统复现。

## 输入与冻结规则

- 单卡 Qwen3-8B，原有锁定 LMCache/vLLM 环境。
- 每任务从公开来源索引 66 开始，取前 16 个能进行答案改变编辑的来源：QA2、QA3、QA9，共 48 个。
- 排除旧 round2_screen 的所有 source_id；不按模型正确率选题。未见指未用于此前本地模型评测，不能排除模型训练数据污染。
- 保留公开输入的 natural4k 原始布局；另制作 early8k 压力布局，移动事实到开头并重复无事实背景。后者不是自然长文。
- 两种布局共用来源，统计按来源聚类，不能当成 96 个独立来源。
- 每题等长替换三次，96 条题链、288 个编辑事件；共 384 条版本输入。由现有规则 oracle 验证答案，分词、输入和构建器哈希留档。
- 冻结后不按结果换题、调预算、选最优窗口；完整报告全部任务及布局。

## 五个方案

full 与 prefix 使用新启动原生服务，分别关闭/启用精确前缀缓存。每轮均重新测量。
三个近似方案均使用严格位置因果 mask、检查层前 KV 写回修正，检查层 1，总预算 floor(N×10%)。
完整问题从最后 Question: 到 assistant/think 模板末尾，全部保留；强制部分占用同一预算，不额外加算。

| 名称 | 其余修复位置 |
| --- | --- |
| query | 余量按 K 差异 top-k |
| tail64 | 强制最后 64（含完整问题），余量按 K 差异 top-k |
| boundary | 完整问题之外，对非首块的开头按相同深度扩展，短块耗尽后将余量给剩余块 |

boundary 排除首块 A，从两处分隔符开头扩展，包含分隔符；最后问题区间不重复计数。
若晚编辑导致全部非首块总长不足 10% 预算，修完它们后从精确首块开头补齐预算；逐输入记录这些额外前缀位置的数量。不按此条件排除样本。这是看模型输出前的结构性预检修正。
其动机来自 [EPIC §4.2](https://arxiv.org/html/2410.15332v3#S4.SS2) 与 [作者评测代码](https://github.com/DerekHJH/epic/blob/main/benchmarks_ours/evals/e2e/main.py#L176-L204) 的块首和完整问题选择。
适配差别：用总长 10% 预算和短块余量转移，保留现有缓存构建、层 1 完整探测以及 K 差异计算；原 EPIC 使用每块固定 k、静态前向选择。
因此只能比较选点思路在共同后端的质量，不能据此评价 EPIC 原系统速度，更不能称为完整 EPIC 或 ProphetKV 复现。

长度不足 1024 的 B′ 准备请求沿用默认 top-k；测量主请求的问题均经预检确认完整落在最后 64。
所有组承担同样的完整 token 边界解析、选点同步和哈希日志开销。除了数量/问题覆盖，还逐请求核对 boundary 所选位置的哈希。

## 执行、统计与继续条件

先检查 CPU 和 GPU 选点、输入分割、原工程保护记录与上游版本。
两轮分别按 query/tail64/boundary 与反序运行，每组新服务和新缓存。每轮第一组先新测 full、prefix；同轮其他组只引用该轮 native 结果。
HTTP 单客户端 TTFT 包含 B′ 完整准备耗时与主请求首 token，含检索、搬运、探测、修复、日志、调度；不含首次播种、分词和后续 decode。
报告任务正确率、full 正确但近似错误及反向情况、均值/P95 TTFT、按任务/布局/编辑次序分解和重复一致性。
95% 区间按来源聚类 bootstrap 1500 次，携带布局、编辑与重复；两次运行不增加独立样本。

主要比较 tail64-query，边界比较与各分层为探索性结果。筛查继续信号为主要比较准确率至少 +3 个百分点、区间下界大于零，且均值和 P95 TTFT 点估计增幅均不超过 5%；这不是正式多重检验或非劣效性结论。
若未通过，不继续把固定 tail64 当主创新；查看共同问题刷新后仍稳定存在、full 能答对的失败案例，再决定是否值得设计机制。
即使通过，也只支持进一步验证；还需要更忠实强基线、更多真实任务/模型与并发服务证据。

三次编辑使用上游实际缓存保存行为，本轮不声称实现了每轮近似 CPU 缓存回写，不证明长期误差积累。
数据与日志写入数据盘独立工程，新分支 experiment/query-fair；保留旧分支与原 vLLM 工作区。
轮询 GPU 0/1，连续三次 30 秒无进程、显存≤100 MiB、利用率≤5%才启动，整轮固定一张卡；每次等待最多 24 小时。
完成/失败/中断均还原补丁并校验默认环境，自动生成统计和逐事件报告。

```bash
.venv/bin/python scripts/build_query_fair_input.py --output data/query_fair_v1.json
.venv/bin/python scripts/run_query_fair.py --validate-only --output /tmp/unused
.venv/bin/python scripts/run_query_fair.py --output results/query_fair_NEW --gpus 0 1
.venv/bin/python scripts/analyze_query_fair.py --run results/query_fair_NEW
```

这些命令依赖已有本地公开来源、模型和锁定环境；原始数据未纳入 Git。本文件为运行前协议，结果在运行目录单独报告。
